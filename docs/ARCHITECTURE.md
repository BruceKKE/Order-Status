# 架构与数据口径

## 数据流

浏览器只访问 Cloudflare Worker。Worker 校验登录会话后，使用服务端 Secret 获取飞书 tenant access token，再以只读方式读取多维表格。业务数据不会写入 Git、静态资源或浏览器 localStorage。

Worker Cache API 缓存成功响应 60 秒，前端每 60 秒刷新一次，并显示飞书数据生成时间。缓存副本使用可缓存响应头，返回浏览器的副本始终改为 `Cache-Control: no-store`。DTO 架构变更时同步升级内部缓存版本，避免新前端读取旧结构缓存。刷新失败时只保留本次页面会话中的上次成功数据。

原 GitHub Pages 地址只提供静态跳转，不承载业务数据。登录页、仪表盘和 WincoTek Logo 均由 Worker Static Assets 提供。

## 飞书读取白名单

Worker 只读取以下 8 张表，表 ID 集中定义在 `src/index.js` 的 `TABLES` 常量中：

| 表 | 用途 |
| --- | --- |
| `客户档案` | 客户名称、联系人和催款邮箱解析 |
| `客户订单` | 订单金额、成本、利润和状态 |
| `客户订单明细` | 订单产品行数与订单关系 |
| `供应商订单` | 采购、原币、付款和交付状态 |
| `供应商订单明细` | 采购行数与供应商订单关系 |
| `出货CI` | CI 金额、日期、状态和客户关系 |
| `出货明细` | CI 出货行数与明细关系 |
| `应收计划` | ARCI 计划应收、已收和未收 |

服务端使用 Feishu record ID 建立关系图，但对浏览器只返回稳定业务编号、聚合值和行数，不返回内部 record ID 或完整明细行。

## HTTP 路由

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/` | GET | 静态登录页和仪表盘 |
| `/api/session` | GET | 返回当前会话是否有效 |
| `/api/login` | POST | 校验访问密码并设置 12 小时签名 Cookie |
| `/api/logout` | POST | 清除会话 Cookie |
| `/api/order-status` | GET | 登录后返回最小化订单 DTO |

会话 Cookie 使用 HMAC-SHA256 签名和随机 nonce，并设置 `HttpOnly`、`Secure`、`SameSite=Strict`。登录和退出请求要求同源 `Origin`。旧的 `cf-access-jwt-assertion` 请求头不能绕过认证。登录失败按来源 IP 做 15 分钟窗口的尽力限速，并采用指数退避；它不能代替高熵强密码。

## 业务粒度

- 销售额、订单成本、订单利润：`客户订单` 粒度，订单号优先使用 `销售PI号`，缺失时回退 `客户PO号`。
- 采购与应付：`供应商订单` 粒度，保留原币金额和折算 USD 金额。
- 发货：以 `出货CI` 表头展示 CI 金额、客户和状态；`出货明细` 仅按 `对应CI` 关系统计行数。当前页面不在发货层重新连接销售明细或采购明细。
- 收款：仅使用 `应收计划` 中的 ARCI 计划应收、已收和未收；不使用手工布尔值推断收款状态。

客户应收汇总仍是 CI/ARCI 粒度：

- 应收总额 = 活动 `ARCI-*` 计划的 `未收金额` 合计，只统计未收金额大于 0 的 CI。
- 已到期应收 = 到期日不晚于 Asia/Singapore 当天的未收金额；先在每条活动 ARCI 计划上判断，再汇总到 CI 和客户，避免分期计划互相污染。
- 逾期超过 2 个月 = 到期日早于当天超过 60 天的未收金额，同样按 ARCI 计划逐条判断。
- 下钻行显示 CI 和其 `对应客户订单` 的业务编号；一个 CI 关联多个订单时保留全部订单号，不把 CI 应收金额虚构拆分到单个订单。
- 业务概览“近期 CI 应收提醒”同样排除已收清 CI。
- 缺失 `对应CI` 关系时，仅按 `ARCI-<ci_record_id>` 契约回退；仍无法解析的活动计划不计入金额并在页面显示数据质量警告。关系与编号后缀指向不同 CI 时也不计入金额，同时给出冲突警告，要求回源核对。
- 月度回款计划保持 ARCI 计划粒度：选择月份 `M` 时，纳入所有 `到期日` 月份不晚于 `M`、且当前 `未收金额 > 0` 的活动计划。以前月份的欠款会在后续每个月持续结转，只有 ARCI 核销为 0 后才移除。分期计划逐条保留，即使 CI、到期日和币种相同也不合并；页面与邮件使用同一组明细，并按币种分别合计。该视图展示当前余额，不重建历史时点余额。

页面反映 ARCI 的核销同步状态，不是银行现金台账。已确认收款若尚未完成分摊到 ARCI 的同步，仍会暂列未收；不得在网页端用订单布尔值或手工例外覆盖。

汇总卡默认使用 USD 展示。截至 2026-08-08 验证，飞书客户订单和 CI 均为 USD；代码不会把非 USD 销售额或 CI 金额自动换算后再汇总。供应商订单则明确保留原币金额和折算 USD 金额两个字段。

前端只读，不提供新增、删除、手工结单或收款写回入口。飞书是唯一事实源。

## 前端筛选

客户应收、客户订单和 CI 发货栏目从当前 DTO 动态提取客户名称，供应商订单动态提取供应商名称，并在浏览器内提供可搜索的多选下拉筛选。名称勾选使用精确匹配，文本搜索仍覆盖业务单号、CI、日期和状态；筛选只影响当前栏目展示，不改动汇总口径或服务端数据。筛选状态仅保存在当前页面内存，刷新飞书数据时保留，退出或重新加载页面后清空。

## 月度回款与邮件草稿

服务端只为存在未收 ARCI 的客户返回 `customerEmail`、`contactName` 和最小化 `schedules`。邮件草稿要求 CI 只能解析到一个客户；客户关系缺失或多选时，页面显示质量错误并禁用该组邮件按钮，避免把商业金额发给错误客户。邮箱和联系人来自 `客户档案`，缺邮箱时仍可生成无收件人的草稿供人工补充。

“打开催款邮件草稿”使用经过编码的 `mailto:` 链接启动本机默认邮件客户端，不调用邮件发送 API；主题控制字符和异常邮箱会被过滤。正文过长时不再打开可能被截断的链接，而是复制完整收件人、主题和正文；页面也始终提供“复制邮件内容”作为回退。最终收件人、金额、收款分摊和银行记录必须由操作人核对后手工发送。

## 安全边界

- 所有飞书凭据和登录密钥只能存为 Cloudflare Worker Secret。
- 静态 HTML 不含业务记录；未登录 API 返回 401。
- 动态文本在前端插入 HTML 前统一转义，金额字段强制转换为数字。
- 页面设置 `noindex,nofollow`，但这不是访问控制；真正的控制在 Worker API 会话校验。
